# Audit: Downloads & Offline (Download Center + 4 managers)

Scope read: `src/components/downloads/*`, `src/stores/downloadProgressStore.ts`, `src/utils/{jellyfinDownloadManager,jellyfinOfflineQueue,musicDownloadManager,absDownloadManager,absOfflineQueue,connectivityManager,storage,fileExport}.ts`, Calibre path in `src/stores/libraryStore.ts:1028-1135` + `src/App.tsx:2145-2160`, startup/reconnect hooks `src/App.tsx:1464-1720`, `src-tauri/src/commands/filesystem.rs` (`download_file`, `read_directory`, `is_path_safe`), offline views (grep-level), roadmap.

Architecture in one line: four independent managers (Jellyfin video = serial localStorage queue; JellyMusic = serial localStorage queue + album/playlist progress; ABS = no queue, fire-and-forget per click; Calibre = one-shot `handleDownload`) mirrored read-only by `downloadCenterStore`. Rust `download_file` streams straight to the **final** filename, no `.part`, no Range/resume, cancel = URL-keyed flag checked between chunks.

Correction to the brief: "season download = 20 parallel" is **not** true for Jellyfin video (`processQueue` is strictly serial, `jellyfinDownloadManager.ts:285-301`) nor JellyMusic (`musicDownloadManager.ts:461-477`). Unbounded parallelism exists only in **ABS** (A6).

|---|---|---|---|
| A1 | **iOS: every app update wipes the whole offline index (files orphaned).** Indexes store **absolute** paths; iOS container UUID changes on update; startup `verify*` prunes every entry whose absolute path no longer exists. Nothing rebases old paths onto the new `downloadPath`. | `App.tsx:1470-1478` (re-resolves `downloadPath` only), `App.tsx:1486-1492` → `verifyDownloadedMedia` (`jellyfinDownloadManager.ts:590-606`), `verifyDownloadedTracks` (`musicDownloadManager.ts:720-752`); `verifyAbsDownloads` (`absDownloadManager.ts:272-289`) from `AudiobookshelfView.tsx:98`. `localPath` written absolute at `jellyfinDownloadManager.ts:398`, `musicDownloadManager.ts:549`, `absDownloadManager.ts:193`. No rebase helper exists (grep `rebase|remap|relocat` → none). | Sideload update via SideStore → launch → "Downloads" empty for video, music, audiobooks; GBs of files still on disk under the new container, unreachable and never deleted (Calibre survives only because it rescans the folder). Fix: store paths relative to `downloadPath` (or rewrite the prefix before verify). |
| A2 | **No queue recovery after crash/app-kill: items stuck in `downloading` forever, `queued` items never start.** Status `downloading` is persisted; `processQueue`/`processMusicQueue` only pick `status==='queued'` and are only invoked from `addToQueue`/`resume`/`retry`. Album progress for music likewise frozen. Fix: on startup reset `downloading→queued` and kick both processors. |
| A3 | **Partial file left at the final path on crash/kill → Calibre lists a truncated book.** Rust writes directly to `folder/fileName` (no `.part`+rename); cleanup only runs on in-process error/cancel. Calibre `read_book_folder` accepts any folder containing a book-extension file, metadata.json optional. | `filesystem.rs:559,622` (create final file), `filesystem.rs:328-387`; `libraryStore.ts:1060-1066`. | Kill app mid-EPUB download → relaunch → book appears in local library with title = filename; opening fails/corrupt. Fix: download to `name.part`, rename on success; startup sweep of `*.part` and index-less folders. |
| A4 | **Jellyfin "Pause" un-pauses itself and leaves a ghost `downloading` row.** `pauseDownload` doesn't `flushPendingSave()` (unlike `removeFromQueue`, line 226). The 2-s throttled snapshot from the last byte event (status `downloading`, bytes N) is written *after* the pause, reverting it. Same stale-snapshot race can drop an item queued while another downloads on a slow link (<~256 KB/s, no byte event within 2 s) — PLAUSIBLE. Fix: flush in every mutator, or keep queue in memory and persist from one place. |
| A5 | **Calibre folder = book title → collisions and destructive deletes.** `bookFolder = ${downloadPath}/${safeTitle}`; delete targets the same computed path. Sanitizer only strips `\/:*?"<>|`. | `libraryStore.ts:1053-1055`, `1114-1118`. | (a) Two books titled "Volume 1" (different series) share a folder: second overwrites `metadata.json`/cover, the folder now has two book files and `read_book_folder` shows only the first; deleting either deletes both. (b) A book titled **"Jellyfin"**, **"JellyMusic"** or **"Audiobookshelf"** → `handleDelete` runs `deleteDirectory(downloadPath/Jellyfin)` = **wipes all video downloads**. (c) Title `.`/`..` → deletes the whole download dir / its parent (passes `is_path_safe` if the parent is an allowed dir). (d) Trailing dot/space titles break on Windows; >255-byte titles fail. (e) Title edited in Calibre after download → delete misses the folder (orphan). Fix: folder = `calibreId` (or `opdsId` hash) + delete by the scanned `LocalBook.path` parent. |
| A6 | **ABS: no queue, unbounded parallel downloads, no cancel, failed partials never cleaned.** Each click calls `downloadAbsItem` directly; only dedupe is "same key". Catch block marks failed and auto-hides after 10 s but never deletes the folder. | `absDownloadManager.ts:120-256` (no queue), `240-252` (no cleanup); call sites `AbsPodcastDetails.tsx:205`, `AbsItemDetails.tsx:230,384`. | Tapping download on 15 podcast episodes → 15 concurrent transfers; one fails → folder with cover + half the files stays forever, invisible in UI; failed row disappears after 10 s with no retry. Download Center shows ABS rows with greyed cancel/retry. |
| A7 | **ABS multi-file books: filename collisions overwrite earlier parts.** Files saved by `audioFile.metadata.filename` (basename only); ABS books often have `CD1/01.mp3`, `CD2/01.mp3`. | A8 | **JellyMusic multi-disc collisions.** Track filename = `${indexNumber} - ${name}` inside `tracks/{albumId}`; disc number (`ParentIndexNumber`) not included. | `musicDownloadManager.ts:523-525`, `491`. | Disc 1 "01 - Intro" and Disc 2 "01 - Intro" → second overwrites first; both index entries point to one file; deleting either track (`deleteDownloadedTrack` → `deleteFile(localPath)`, line 781) removes the other's audio. |
| A9 | **Offline progress queues lose entries added during a flush.** `processJellyfinQueue` loads queue, awaits network per op, then `saveQueue(failedOps)` — overwrites anything appended meanwhile. Duplicate `Sessions/Playing/Stopped` posts from parallel `syncPendingProgress` runs (harmless but noisy). Fix: single-flight mutex + remove-by-id instead of overwrite. |
| A10 | **Offline progress overwrites newer server progress (no timestamp merge).** Jellyfin pending positions and ABS queue are pushed blindly on reconnect; ABS PATCH sets server `lastUpdate=now`. | `jellyfinDownloadManager.ts:727-766`, `jellyfinOfflineQueue.ts:141-154`, `absOfflineQueue.ts:59-70`. | Watch ep offline on phone to 20 min, later finish it on the TV, reopen phone online → phone pushes 20:00 and un-does the TV's progress. | A11 | **Two parallel Jellyfin offline-progress stores, inconsistent auth/route/transport.** `jellyfin_pending_progress` (localStorage, via `api.request` = Rust, SSL-bypass) and `jellyfin_offline_queue` (IndexedDB, via **browser `fetch`**). | A12 | **Downloads/queues survive logout & server removal; stale tokens persisted.** Queue items persist `accessToken` (plain localStorage) and keep downloading with it; `removeJellyfinServer` (`types/settings.ts:288`) and Jellyfin `logout` (`JellyfinContext.tsx:282`) don't touch queues/downloads (grep: no references to queue keys outside managers). Offline-progress ops also carry tokens → after token rotation every op 401s and is retained forever. | `jellyfinDownloadManager.ts:36-40`, `musicDownloadManager.ts:44+`, `jellyfinOfflineQueue.ts:18-49`. | Log out / remove server → its downloads keep running in background; its items still appear in offline library; queued failures retry with dead token indefinitely. |
| A13 | **Cancel during the pre-transfer phase downloads the whole file, then deletes it.** Jellyfin sets `activeDownloadUrl` only after poster/backdrop/HEAD (line 362); cancel before that only calls an `AbortController` that nothing listens to. Music sets URL before HEAD, but Rust clears any stale flag for that URL when `download_file` starts (`filesystem.rs:634-637`), so an early cancel is erased. | `jellyfinDownloadManager.ts:310-392`, `musicDownloadManager.ts:497-543`, `filesystem.rs:634-637`. | Cancel a 20 GB movie in its first second → it silently downloads all 20 GB, then `cleanupPartialDownload` deletes it; the serial queue is blocked the whole time. Fix: check queue status right before `downloadFile`; clear stale flags at enqueue, not at start. |
| A14 | **Video always saved as `video.mp4` regardless of container; static original only.** `stream?static=true` returns the source container (MKV/AVI/TS) unchanged. | `jellyfinDownloadManager.ts:345,380,398`. | MKV/HEVC/DTS sources: wrong extension, and on iOS (memory: WKWebView can't play MKV/AC3) offline playback fails outright; on desktop codec-dependent. No transcode option (see B4). |
| A15 | **Stalled transfer hangs the serial queue forever.** reqwest clients have `connect_timeout` only, deliberately no total timeout, and there's no idle/read timeout in the chunk loop. | `http.rs:39-82`, `filesystem.rs:644-697`. | Wi-Fi handoff / NAT drop mid-stream → `stream.next()` may never resolve; item stays at 63 %, every later item waits. | A16 | **JellyMusic album never completes if its last track was already queued by a playlist.** `addTrackToQueue` on an already-queued track only patches `playlistDownloadId`, not `albumDownloadId`; `updateAlbumProgress` is called only when `item.albumDownloadId` is set. | `musicDownloadManager.ts:185-194`, `591-593`. | Download playlist, then the album containing one of its pending tracks; if that shared track finishes last, album sits at "11/12 tracks" forever (Download Center row never clears, no `DownloadedAlbum` entry). |
| A17 | **No disk-space pre-check; disk-full burns retries and leaves dir skeletons.** Write error deletes the file but the managers auto-retry ×2 with backoff (`MAX_AUTO_RETRIES`), then each next queue item hits the same error. | A18 | **Download Center perf: full rebuild on every byte event.** `useDownloadProgressStore.subscribe → rebuild()` re-parses 3 localStorage queues + album/ABS lists + sorts on every 512 KB event; Jellyfin also re-parses + rewrites its queue per event (`updateQueueItemBytes`), music `saveMusicDownloadQueue` per status change notifies all. | `downloadCenterStore.ts:558-561`, `410-434`; `jellyfinDownloadManager.ts:525-535`. | On a 50 MB/s LAN that's ~100 rebuilds/s with JSON.parse of a large queue (20-ep season + 300-track playlist) → jank on phones. | A19 | **Calibre: format/extension mismatch.** `ext = formats[0]` while `url = book.downloadUrl` (an OPDS acquisition link possibly of another format). | `libraryStore.ts:1031-1051`. | Book with formats `[PDF, EPUB]` whose OPDS link is the EPUB → saved as `Title.pdf` → opened by the PDF reader → error. PLAUSIBLE (depends on OPDS link order). |
| A20 | **ABS rows reorder on every rebuild.** `mapAbs` sets `addedAt: Date.now()` each rebuild, so sort by `addedAt` always pushes ABS last and timestamps churn. | `downloadCenterStore.ts:365`. | Cosmetic list jumping; also breaks any future "oldest first". |
| A21 | **Download-path change has no migration.** Settings path change (`App.tsx:282`) → Calibre books vanish (scan new dir), Jellyfin/music still point at old absolute paths, `cleanupPartialDownload`/ABS `getAbsFolder` compute from the new path → deletes miss the real folder. | `jellyfinDownloadManager.ts:542-546`, `absDownloadManager.ts:108-114,260-269`. | Delete an ABS book after moving the folder → index entry removed, files remain forever. |
