# Live TV audit (Mediamaster): bugs, missing features, polish, roadmap

**Scope:** `src/components/livetv/{LiveTVView,EPGGrid,LiveTVPlayer,index}.tsx` (1,361 LOC total). Also checked: the App.tsx mount (l.2405-2430), navigationBus, mediaSessionOwner, orientation.ts, useAudioOutputDevice, usePullToRefresh, haptics, and the JellyfinPlayer feature set for comparison.
**Jellyfin 12 API compliance: PASS.** All hand-rolled calls send `Authorization: MediaBrowser Token=…` (LiveTVView:157, LiveTVPlayer:136,166). URL auth uses `ApiKey=` (LiveTVView:126, LiveTVPlayer:206-207). The code calls `POST /LiveStreams/Open` (LiveTVPlayer:164), not `/LiveTv/LiveStreamings/Open`. There are no `/emby/` prefixes, no `X-Emby-*` headers and no `api_key`.
**Phone immersive player (per the memory note): verified.** Fullscreen phone mode is `fixed inset-0 z-[70] w-screen h-dvh touch-none` (l.388). Gestures: tap toggles controls, double-tap toggles mute, a horizontal swipe changes channel, a swipe down goes to PiP, and the 24px left edge is reserved for swipe-back (l.326-377). The landscape lock is best-effort (l.293-319).

**Live TV surface today:** a channel list (≤1000) and a fixed 6-hour EPG window. The EPG is fetched once. Tapping a channel opens a fullscreen player or a corner PiP. Controls are channel up/down, mute, volume and guide. Radio has an audio-only profile. There is nothing for recordings, timers, favourites, program details, timeshift or session reporting.

## A) Bugs and likely defects (ranked)

| # | Severity | Where | Defect | Concrete failure scenario |
|---|---|---|---|---|
| A1 | **High** | LiveTVPlayer.tsx:119-222 (whole file) | **Live streams are never closed and the playback session is never reported.** There is no `POST /LiveStreams/Close?liveStreamId=`, no `/Sessions/Playing{,/Progress,/Stopped}` and no `DELETE /Videos/ActiveEncodings?playSessionId=` anywhere under `livetv/` (grep: only the `/LiveStreams/Open` at l.164). `PlaySessionId` and `LiveStreamId` from PlaybackInfo/Open are thrown away. The effect cleanup (l.221) only sets `cancelled=true`. | A user zaps through 5 channels on an HDHomeRun or TVHeadend with 2 tuners. Each zap runs Open on a new tuner, and the old tuners and ffmpeg transcodes stay alive until Jellyfin's inactivity/ping timeout. By the 3rd zap you get "no tuner available" or a black screen (see A4). The server dashboard never shows the client as "watching", and the transcode keeps burning CPU after Stop. JellyfinPlayer does report the session lifecycle (JellyfinPlayer.tsx:962/990/1028); Live TV does none of it. |
| A2 | **High** | LiveTVPlayer.tsx:142-176 | **An in-flight Open leaks when you zap quickly.** `cancelled` is checked only *after* `await …/LiveStreams/Open` returns. | A3 | **High** | LiveTVPlayer.tsx:451, 485 | **The Retry button does nothing.** `onRetry` does `setError(null); setIsLoading(true); setStreamUrl(null)`, but the fetch effect's deps are `[channel.id, serverUrl, accessToken, userId, isRadio]` (l.222). | A6 | **High** | LiveTVView.tsx:153-161, 182 | **The guide spinner sticks forever after a non-throwing EPG failure.** `if (!res.success \|\| !res.data) return` exits before `setIsLoadingEPG(false)`, which sits outside `finally`. | Any 4xx/5xx from `/LiveTv/Programs` (including A7's 414) leaves "Loading guide…" spinning in the top bar for the rest of the session, with an empty grid and no error message. |
| A7 | Med-High (**PLAUSIBLE**) | LiveTVView.tsx:151-155 | **The EPG request URL can be too long, and large lineups get truncated.** All channel GUIDs go into the query string: 33 chars per channel, with up to 1000 channels. Kestrel's default MaxRequestLineSize is 8 KB, which overflows at roughly 245 channels. Also, `limit=5000` with no `sortBy` silently cuts off large lineups: 400 channels × 6h × ~2 programs per hour is about 4,800. | IPTV users with M3U lineups of 300–2000 channels are common. Fix: use `POST /LiveTv/Programs` (GetProgramsDto body), or omit `channelIds` (the server already scopes to the user). Then page through results or fetch per visible rows. |
| A8 | Medium | LiveTVView.tsx:189-194; LiveTVPlayer.tsx:700-710; EPGGrid.tsx:181,197 | **Nothing is time-driven: there is no ticking, no polling and no EPG refetch.** `currentProgram` is a `useMemo([selectedChannel, programMap])` and never re-evaluates at a program boundary. `ProgressBar` reads `Date.now()` only on render. | A9 | Medium | LiveTVPlayer.tsx:635-640 vs 279-280, 411-416 | **Channel up/down are inverted in the fullscreen controls.** The ChevronUp button, titled "Previous channel (↑)", calls `onChannelDown`, which goes to idx+1 (the *next* channel). | A13 | Medium | LiveTVView.tsx:304-309 | **Refresh covers the playing stream and resets the guide.** `isLoadingChannels` renders an `absolute inset-0 z-20 bg-gray-900` overlay over the content area, which contains the desktop fullscreen player (`relative w-full h-full`, no z-index). | A14 | Low-Med (**PLAUSIBLE**) | LiveTVPlayer.tsx:203-209 | **The last-resort fallback URLs are wrong for Live TV.** They use `source.Id` (a media-source id) as the item id, and the video path uses `Static=true` raw MPEG-TS, which the comment at l.15 says WebView2 can't decode. `Path` with `Protocol==='Rtmp'` (l.200) can never play in a `<video>`. | If the server returns no `TranscodingUrl`, playback silently fails (it then hits A4's black screen). | A15 | Low-Med | LiveTVPlayer.tsx:160-185 | **`PlaySessionId` isn't forwarded to `LiveStreams/Open`, and `AutoOpenLiveStream` isn't used.** PlaybackInfo is called with `IsPlayback=true` but without `AutoOpenLiveStream=true`, so every zap costs two round-trips. | A16 | Low | LiveTVPlayer.tsx:293-309 | **The phone landscape lock depends on transient activation.** `requestFullscreen()` runs from an effect after the tap. | A17 | Low | LiveTVView.tsx:141-186 | **The EPG fetch has no cancellation or race guard.** A refresh while a fetch is in flight lets an older response overwrite newer state. `channels` changes on every refresh, which triggers a full refetch. | Rapid Refresh taps can show a stale guide. |
