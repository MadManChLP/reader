# Audit: Jellyfin video client (browsing + player)

Scope: `src/components/jellyfin/` (excluding `music/`), `player/**`, `JellyfinView`, the related stores and utils, and `jellyfinDownloadManager` (skimmed).
Method: read-only. I read the files directly, with no web lookups. Line numbers point at the current `master` (clean tree).
Labels: **VERIFIED** = I traced the failure path in code. **PLAUSIBLE** = it depends on runtime or server behaviour I could not confirm.

A pattern behind many bugs: `JellyfinView.tsx:600` renders `<JellyfinPlayer>` **without a `key`**. "Next episode" (whether auto-advanced or picked from the queue) therefore reuses the same player instance with a new `item` prop, and most per-item state is never reset. Bugs A1–A5 all come from this. Adding `key={currentItem.Id}`, or an explicit reset effect on `item.Id`, fixes most of them at once.

## A) Bugs and likely defects (ranked)

| # | Sev | Status | Where | Defect and failure scenario |
|---|---|---|---|---|
| A1 | High | VERIFIED | `JellyfinPlayer.tsx:495-502` | **A downloaded next episode starts at the previous episode's position.** The local branch only calls `setFetchedResumePosition` when `localTicks > 0`. On an item change with no saved progress, `fetchedResumePosition` keeps the previous episode's value. Example: offline binge, ep1 ends at 42:00, ep2 loads, `handleLoadedMetadata` seeks to 42:00, so ep2 is skipped/ends almost at once. Fix: always `setFetchedResumePosition(localTicks)`. |
| A2 | High | VERIFIED | `JellyfinPlayer.tsx:488-492, 955-969, 972-1009` | **Wrong session and position reported when switching episodes while playing.** On Next, the init effect resets `playbackStartedRef=false`. The reportStart effect then runs in the same commit: `isPlaying` is still true because the old video keeps playing until the new `PlaybackInfo` returns, so it POSTs `/Sessions/Playing` for the **new ItemId with the old PlaySessionId and the old position**, then latches. During the same window the 10s progress interval sends `currentTimeRef` (old episode's time) against the new `item.Id`, which can write e.g. 40:00 as ep2's resume point. Fix: pause and clear the time refs on item change, and gate start on `playSessionId` belonging to the current item. |
| A3 | High | VERIFIED | `JellyfinPlayer.tsx:83-84, 547-558, 255-275` | **Audio and subtitle selection leak across episodes.** `selectedAudioIndex` and `selectedSubtitleIndex` are never reset. (a) The default-audio effect only runs when `selectedAudioIndex === null`, so the user's `AudioLanguagePreference` is never applied to ep2+, and the menu shows ep1's stream index even though the stream wasn't requested with it. (b) The subtitle index carries over by *stream index*, not language. On ep2 it can point at a different language, an image sub (silently nothing), or no track at all; the `<select>` then has a value with no option. For a moment the subtitle URL is also built from the new `item.Id` and the old `mediaSourceId`. |
| A4 | Med | VERIFIED | `JellyfinPlayer.tsx:561-582` | **Stale media segments mean Skip Intro appears at the wrong time.** `mediaSegments` is only set when the new item has segments, so an episode without segments inherits the previous episode's intro window. Same pattern for `trickplayInfo` (`:625-660`, never nulled): you get thumbnails with the old dimensions, or 404 sprites. |
| A5 | Med | VERIFIED | `JellyfinPlayer.tsx:107, 1439, 938-949` | **Dismissing Up Next once suppresses it for the rest of the session.** `upNextDismissed` is never reset on item change. Also `handleEnded` → `onPlayNext` never sets `showUpNext(false)`, so the flyout briefly shows the *following* episode at the start of the new one, until `duration`/`currentTime` refresh. |
| A6 | High | VERIFIED | `JellyfinPlayer.tsx:534-541` | **Endless spinner when PlaybackInfo fails.** If `fetchPlaybackInfoWithTrack` returns `null` (server error, 401, network), nothing sets `error`. `videoUrl` stays null and `LoadingIndicator` spins forever with no Retry or Close overlay. Also, `lastInitializedItemIdRef` is set before the fetch (`:504`), so it never retries even if `api` or `user` arrives later. |
| A7 | High | VERIFIED (logic) | `JellyfinPlayer.tsx:1566, 58, 674-677, 1206-1214` | **After an audio-track switch, volume, output device and PiP state are lost.** `<video key={playSessionId}>` remounts the element on every track switch. (a) The `[volume]` sync effect doesn't re-run, so the new element plays at 100% while the slider shows e.g. 30% (desktop). (b) `useAudioOutputDevice(videoRef,'video')` has no `reapplyKey`, so `setSinkId` is never applied to the new element and audio jumps to the default device. That breaks the user's Voicemeeter routing. (c) PiP listeners are attached once with `[]` deps, so they are bound to the old element. Fix: pass `playSessionId` as `reapplyKey` and re-apply volume, playbackRate and listeners on remount. |
| A8 | Med | VERIFIED (logic) | `JellyfinPlayer.tsx:1157-1160, 1333` | **The first tap after a volume/brightness swipe is swallowed (phone).** `swipeConsumedTapRef=true` is set on every completed vertical swipe, expecting a synthetic click. Browsers do not fire `click` after a touch that moved past slop, especially with `preventDefault` on `touchmove`. The flag stays set and eats the next real tap (controls toggle or double-tap seek). Fix: clear the flag on the next `touchstart`, or a short timeout. |
| A9 | Med | VERIFIED | `JellyfinPlayer.tsx:1070-1075` | **Controls hide mid-scrub on phone.** The phone auto-hide timer only restarts on `showControls`, `isPlaying` or `isLocked` changes. Dragging the progress bar, opening the chapter list, or tapping seek buttons doesn't reset it, so after 3s the controls fade out (`pointer-events-none`) under the user's finger. |
| A10 | Med | VERIFIED | `JellyfinPlayer.tsx:1178-1196` | **The keyboard handler has no editable or modifier guards.** (a) Arrow keys on a focused `<select>` in SettingsMenu change the track *and* seek or change volume. (b) Ctrl+K (global search, `App.tsx:1724`) also toggles play/pause via the `'k'` case. (c) Esc while the desktop SettingsMenu, ChapterList or QueuePanel is open closes the **whole player** instead of the popover. Those popovers have no Esc or back handling. |
| A11 | Med | VERIFIED | `player/` (no `registerBackHandler` anywhere), `PlayerControls.tsx:342-358, 411-423` | **On phone, the back/edge-swipe gesture closes the player instead of an open panel.** QueuePanel and ChapterList don't register back handlers, so `dispatchBack('swipe')` reaches `JellyfinView` (`:164-172`), which tears down playback. Only the SettingsMenu works, because it is a BottomSheet. This breaks the project convention that every overlay registers a back handler. |
| A12 | Med | VERIFIED | `JellyfinPlayer.tsx:1412-1422, 1552` | **The mouse wheel anywhere in the player changes volume, including while scrolling** the QueuePanel or ChapterList lists. `e.preventDefault()` inside React's passive `onWheel` is ignored and logs a console warning. Fix: skip the handler when the target is inside a scrollable panel. |
| A13 | Med | Likely | `JellyfinPlayer.tsx:209-213`; no `'Chapters'` field requested anywhere (`grep`) | **Chapters are effectively always empty.** They are read from `item.Chapters` (never requested in `JellyfinItemDetails.tsx:129-139`, `JellyfinView` queue fetch, or Home) or `MediaSources[0].Chapters`. `MediaSourceInfo` has no `Chapters` property in the Jellyfin API. So chapter markers, the chapter list, prev/next chapter, and the chapter-name intro fallback (`:592-601`) never appear. The trickplay fetch already loads the full `GET /Items/{id}`; take `Chapters` from that response. |
| A14 | Med | VERIFIED | `JellyfinPlayer.tsx:864, 1517-1521` | **No fallback to transcoding when direct play fails.** `handleError` just shows "Failed to load video", and Retry reloads the same URL. If `canPlayType` or MediaCapabilities over-promise (e.g. an MKV whose audio is fine but the container fails), the item can't be played. Jellyfin-web retries with `EnableDirectPlay:false`. Retry should call `fetchPlaybackInfoWithTrack(audio, sub, true)`. An expired transcode session also needs new PlaybackInfo, not `load()`. |
| A15 | Med | VERIFIED | `JellyfinPlayer.tsx:534, 547-558` | **The preferred audio track is UI-only on the first play.** Initial PlaybackInfo is requested with `audioIndex=null`. The default-audio effect then marks the preference-matching track as selected, but nothing re-requests the stream. With DirectPlay the `<video>` plays the container's default track, so the menu says "German" while English plays. The `MediaSource.DefaultAudioStreamIndex` the server returns isn't used either. |
| A16 | Med | VERIFIED | `JellyfinPlayer.tsx:513-521` | **Opening a watched item silently un-marks it.** Every play of a `Played` item sends DELETE PlayedItems before playback starts. Peeking at a watched movie for 5s leaves it "unwatched" in every view, and the watched badge on the series is lost. Neither Jellyfin-web nor Swiftfin does this. The server already handles re-watch progress. |
| A17 | Med | VERIFIED | `JellyfinItemDetails.tsx:380-387, 405-413, 829-836, 1144, 1512, 1575, 1879`; `JellyfinHome.tsx:765-774, 1011, 1161, 1332` | **Watched and favorite toggles never revert on failure.** `appApi.request` resolves `success:false` and doesn't throw (the player documents this at `:986-988`). These handlers only revert in `catch`, so an offline or 401 toggle shows success. MovieDetails sets `setWatched(!watched)` regardless of the result. Offline toggles are also never queued (unlike `video_played` in the player). |
| A18 | Low-Med | VERIFIED | `JellyfinPlayer.tsx:517, 894`; Details and Home lines in A17 | **Legacy user-scoped routes.** `/Users/{userId}/PlayedItems/{id}` and `/Users/{userId}/FavoriteItems/{id}` are used everywhere. CLAUDE.md says to use `/UserPlayedItems/{id}` (and `/UserFavoriteItems/{id}`), which take the user from the token. Concrete bug at `:877`: `const userId = user?.Id \|\| ''` builds `/Users//PlayedItems/{id}` when `user` is missing (offline-auth case), and it also enqueues `userId:''`. No `X-Emby-*`, `api_key=` or `/emby/` regressions were found in this section. |
| A19 | Low-Med | PLAUSIBLE | `JellyfinPlayer.tsx:451, 457` | **Hard-coded `DeviceId: 'reader-app'` in stream URLs.** Every install shares one DeviceId, which also differs from the SDK's per-install id (`JellyfinContext.tsx:73`). Jellyfin kills transcode jobs per DeviceId when a new stream starts with a different PlaySessionId, so phone and desktop transcoding at the same time can kill each other. It also mislabels sessions in the dashboard. Use the stored `jellyfin_device_id`. |
| A20 | Low | VERIFIED | `JellyfinPlayer.tsx:1016-1018` | **No Stopped report when closing before the first `timeupdate`** (`lastKnownTime <= 0` returns early). The server session and any transcode started by PlaybackInfo/HLS linger until timeout. The same happens when the player closes before `playbackStartedRef` latches. |
| A21 | Low | VERIFIED | `JellyfinPlayer.tsx:1230-1231, 1246` | **MediaSession issues.** Seek uses a hard-coded ±10s (ignores the user's seek settings, default forward is 30). There are no `nexttrack`/`previoustrack` handlers for episodes. `playbackRate:1` is fixed. The effect depends on `isPlaying` and `duration`, so it rebuilds metadata and artwork on every play/pause. |
| A22 | Low | VERIFIED | `JellyfinPlayer.tsx:1282-1292` | **Stats for Nerds:** `bitrate` is always `0`. The video and audio codec come from the *source* stream, so a transcode still shows "HEVC/TRUEHD" instead of the delivered H.264/AAC. |
| A23 | Low | VERIFIED | `JellyfinLibrary.tsx:182-191` | **The genre filter only lists genres found in the first page** (first 100 items when unfiltered). Genres that only appear deeper in a large library can't be selected. Use `/Genres?parentId=`. |
| A24 | Low | VERIFIED | `jellyfinDownloadManager.ts:345, 378, 398` | **Downloads save the original static file as `video.mp4` whatever the container.** MKV, AVI or AC3/DTS originals saved as `.mp4` will often fail to play offline in WebView2, and *always* on iOS (WKWebView can't play MKV). The online iOS profile avoids this by forcing HLS, but downloads have no equivalent. See B3. |
| A25 | Low | VERIFIED | `JellyfinHome.tsx:238-259` | **Hero building runs one `getItems` per series serially** (up to ~8 sequential round trips) before the hero renders. Batch with `ids: [...seriesIds]`. |
