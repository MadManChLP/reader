# Reader audit (Calibre tab: EPUB / PDF / Manga)

Scope read in full: `src/components/Reader.tsx`, `reader/EpubReader.tsx`, `reader/epubStyles.ts`, `reader/PdfReader.tsx`, `reader/pdfText.ts`, `reader/MangaReader.tsx`, `reader/types.ts`, `reader/AudiobookControlsMenu.tsx`, `pdf-annotations/*` (canvas/store/storage), `PageThumbnailSidebar.tsx`, `utils/readerPreferences.ts`, `utils/navigationBus.ts`, `BookDetails.tsx`, `BookCard.tsx`. Also checked: `App.tsx` reader mount / Esc / back handler (l.1740-1768, 2205-2235, 2817-2833), `stores/libraryStore.ts` `updateProgress`/`syncPush`/`handleRead` (l.848-1027), `node_modules/epubjs` 0.3.93 (`rendition.js` l.803-813, `managers/views/iframe.js` l.93-99), `react-pdf` 10.3 `Page/TextLayer.js`. HeroCarousel only skimmed.

No reader file imports `IS_PHONE`/`useIsPhone`/`haptics`, and none calls `blockGlobalEsc`/`registerBackHandler`, except PdfReader's search bar (`PdfReader.tsx:884`). The phone experience is the desktop reader with a few `phone:` paddings.

## A) Bugs / defects (ranked)

| # | Where | Defect and concrete failure |
|---|---|---|
| A1 | `EpubReader.tsx:249-254`; `App.tsx:2205-2208`; `libraryStore.ts:908, 926` | **EPUB progress percentage is always `undefined`, so 0 gets stored.** epub.js only fills `location.start.percentage` when `book.locations` has been generated (`rendition.js:803-808`: `locationFromCfi` returns null on empty locations). Nothing in `src/` calls `book.locations.generate()` or `load()` (grep). `onProgress(loc, undefined)` then becomes `percentage ?? 0`. Effects: (a) `addStartedBookId` never runs because it needs `percentage > 0`, so locally the EPUB never enters the started index. (b) The BookCard progress bar stays empty, since `BookCard.tsx:49-51` uses `book.percentage`. (c) Auto "finished, mark read" (`>0.99`) can never fire for EPUB. (d) The server gets no percentage. Fix: after `book.ready`, `await book.locations.generate(1600)` (cache the JSON per book in storage and `locations.load()` it next time). That also enables time-left and page-of-N display. |
| A2 | `EpubReader.tsx:208-209` | **Security: `allowScriptedContent: true`.** epub.js builds the iframe sandbox as `"allow-same-origin" + " allow-scripts"` (`iframe.js:94-96`). Scripts inside the EPUB then run same-origin with the app. They can reach `window.parent` and the Tauri IPC (`__TAURI_INTERNALS__`), which means fs and http commands. Any EPUB from the Calibre library or an OPDS feed is untrusted input. Remove the flag. If interactive EPUB3 ever matters, it needs a separate, opaque-origin path. |
| A3 | `EpubReader.tsx:257-263` | **One arrow press turns two pages while focus is in the book.** `handleKey` is registered for both `rendition.on('keydown')` and `rendition.on('keyup')`, and it ignores `e.type`. After the user clicks into the text (iframe focus), each arrow press fires next/prev twice. |
| A4 | `EpubReader.tsx:264-268` vs cleanup `281-288` | **Leaked window `keydown` listener.** The `return () => removeEventListener` is the return value of the async `loadBook()`, so it is discarded. The effect cleanup never removes the listener. After closing an EPUB, ArrowLeft/Right anywhere in the app calls `next()`/`prev()` on a destroyed rendition (errors). Every opened EPUB adds another listener. The handler also has no `isEditableTarget` check, so arrow keys typed in the "Add Bookmark" input (`Reader.tsx:658`) turn pages. |
| A5 | `App.tsx:1767`; `Reader.tsx` (no Escape handler; only the bookmark input at l.671); `EpubReader`/`MangaReader` (none) | **Esc does nothing in the reader.** App blocks global Esc-as-back while `isReading`, on the basis that "readers own the keyboard". But no reader closes itself, its TOC, its settings panels or its thumbnail sidebar on Esc. Only the PDF search/select mode reacts. On desktop the user cannot leave a book with Esc. Mouse-back/edge-swipe close the **whole reader** even when a panel is open (`App.tsx:2219-2225`), because Reader registers no back handler for its own panels. |
| A6 | `PdfReader.tsx:439-444, 549-589, 642-687` | **PDF scroll modes (vertical/horizontal) lose and overwrite progress.** Nothing scrolls the container to `pageNumber`: resume opens at page 1 while state says page N. The first scroll event then sets `pageNumber` to about 1, and `onPageChange` pushes that to the server, so the saved position is overwritten. TOC clicks, thumbnail clicks, the header page input, and Arrow/Home/End all just change the number with no visual jump. `PageUp/PageDown` call `preventDefault()` and therefore block native scrolling in scroll-v. |
| A7 | `PdfReader.tsx:631-634, 1059-1111` | **PDF scroll modes render every page eagerly.** `pagesToRender` is `[1..numPages]`, and each page is a full `<Page>` canvas plus a text layer (text layer is on whenever status ≠ 'absent', `l.901`). There is no virtualization or IntersectionObserver. A 400-page PDF means 400 canvases at full width, which can get the WebView killed on iOS/Android (the same class of problem as the iOS CBR black screen in MangaReader's comments). |
| A8 | `Reader.tsx:329-333, 897-918`; `PdfReader.tsx:466-471, 726-736, 787`; `libraryStore.ts:885-951` | **Navigation without reading intent commits progress and can mark the book read.** Every page change runs `setItem` and a server PUT, with no debounce: each step of a slider drag, each keystroke in the page input, each search-hit jump, and End. When the page reaches `numPages`, percentage is 1.0 > 0.99, which runs `syncToggleReadStatus` and `removeStartedBookId`. Scrubbing to the last page to check the index, or a Ctrl+F hit on the last page, marks the book **read on the server** and drops it from Continue Reading. Search also never returns the reader to the original page. Fix: debounce pushes (about 2 s plus flush on close), commit slider position on `pointerup`, and require some dwell or an explicit action before auto-marking read. |
| A9 | `MangaReader.tsx:448-449, 167-224, 268-286, 393-424` | **Manga blob-URL leaks.** (a) The unmount cleanup iterates `imageCache` from the effect's first-render closure (an empty Map), so on close **none** of the cached page blobs are revoked. (b) Thumbnail-cache blobs (both paths) are never revoked. (c) Concurrent `updateImageCache` runs during fast page turns each start from their own `imageCache` snapshot and `setImageCache(newCache)` overwrites the other run's map. URLs extracted by the losing run are dropped without `revokeObjectURL`. PLAUSIBLE: because the visible page is skipped when `extractingRef` already has it, the final published map can lack the current page, leaving the "Loading page N…" spinner up until the next turn. |
| A10 | `Reader.tsx:258-282, 306, 883, 896` | **Chrome auto-hide conflicts.** (a) The header's hide condition only exempts `showSettings`, `showToc` and `showAudiobookControls`. The **PDF settings dropdown** (`showPdfControls`) and the **bookmark dialog** fade out and become `pointer-events-none` after 3 s without input, which on phone happens while the user is reading the options. (b) `mousedown` and `touchstart` call `resetIdle`, so **every page-turn tap or click brings the toolbar back** for 3 s. The chrome flashes on each turn instead of toggling on a center tap. |
| A11 | `EpubReader.tsx:44-68, 292-296` | **EPUB on phone: swipe and tap page turns do not work over the text.** The touch handlers sit on the wrapper div, and touches inside the epub.js iframe never bubble to it. Only the padding margins react. The only working way to turn pages is the floating footer buttons, which are hidden while idle. epub.js re-emits iframe events through `rendition.on('touchstart'/'touchend'/'click')`, and the swipe/tap-zone logic should be attached there. |
| A12 | `Reader.tsx:33-61` | **Format choice and CBT support.** Reader always uses `book.formats[0]`, so a book with `[PDF, EPUB]` can never be opened as EPUB. `cbt` (and `cb7`) fall through to "Unsupported format", even though `isComicFormat` in sync treats CBT as a comic and the project doc lists CBT sync. |
| A13 | `libraryStore.ts:912-914` | PLAUSIBLE impact, code verified: `updateProgress` writes `selectedBook.progress = percentage`, a fraction. This contradicts the project convention that `progress` = position (page/CFI). Reader receives `book.progress` as a fraction while open. Any remount of the Reader (for example `ReaderErrorBoundary` retry) would compute `initialLocation` from it: for EPUB `0` is falsy, so the book reopens at the start, and for PDF/Manga `parseInt(0.4)` gives 0, i.e. page 1. |
| A14 | `Reader.tsx:324-336` | PDF page input is controlled and only accepts valid values. The last digit cannot be backspaced (the empty value is rejected and the field snaps back). Typing "150" navigates to 1, then 15, then 150, and each step produces a progress PUT (see A8). It should commit on Enter or blur. |
| A15 | `Reader.tsx:512`, `308`, `449`, `472` | Accessibility and touch: the EPUB bookmark delete button is `opacity-0 group-hover:opacity-100`, so it is invisible on touch. The close (X), EPUB settings and fullscreen buttons have no `title`/`aria-label`, so screen readers announce unlabeled buttons. The click zones are unlabeled `div`s. |
| A16 | `Reader.tsx:219-229, 472` | The fullscreen button shows on phone, but the iPhone WKWebView has no element Fullscreen API. `requestFullscreen` rejects and only a `console.error` is logged, so the button is dead on iOS. It should be hidden under `IS_PHONE` (the reader is already a fixed full-viewport overlay). |
| A17 | `annotationStore.ts:109-117` | PLAUSIBLE race: `cleanup()` is async (`await flushAnnotations()` then `set({annotations:null})`). If a new PDF's `initialize()` resolves first (close and reopen quickly while a debounced save is pending), the old cleanup nulls the new book's annotations. `addStroke` and the other actions then silently no-op (`if (!state.annotations) return`). It should guard with `if (get().bookId === closingId)`. |
| A18 | `MangaReader.tsx:508-520` | The keyboard effect deps omit `spreadInfo`/`imageCache`, so `goToNext` captures a stale `spreadInfo`. In double mode an arrow press right after spread detection can step 2 pages over a spread. Minor; PLAUSIBLE frequency. |
| A19 | `Reader.tsx:87-108` vs `PdfReader.tsx:703-713, 860-879` | pdfText gating is inconsistent: the toolbar search button refuses while status is 'checking' (toast), but Ctrl+F opens search anyway. Esc pressed in `TextNoteEditor` (its own Esc handler, `TextNoteEditor.tsx:59`) also closes the search bar or select mode through the window listener. Minor. |
| A20 | `Reader.tsx:135-139` | An extra full copy of the PDF (`new Uint8Array(pdfDataForSidebar)`) is made eagerly and held for the whole session, even if the thumbnail sidebar is never opened. Opening the sidebar also loads a second pdf.js document. On phone this is a memory cost on top of A7. It should be created lazily when `showToc` first opens. |

**pdfText.ts (new this week): no correctness bug found.** Item indices line up with react-pdf: both use `page.getTextContent()` items and the `itemIndex` from `TextLayer.js:140`. Ligature/diacritic mapping via `normToRaw` is sound, and the HTML is escaped. Remaining issues: the behaviour issues above (A8 search moves synced progress, A19 gating), `textIndexRef`/`rendererCacheRef` are never pruned (full-text index of every page is kept), every `docVersion` bump (display-mode switch) re-runs the search and re-jumps to the first hit at or after the current page, and in scroll modes our `getTextContent` duplicates react-pdf's per page.
